## رتبه‌بندی اعتبار

1. **بالا:** مقالهٔ داوری‌شده/نسخهٔ نهایی arXiv برای ادعاهای آزمایشگاهی محدود به همان benchmark؛ OWASP و NIST برای ریسک/حکمرانی؛ مستندات API رسمی برای رفتار جاری محصول خودشان.
2. **متوسطِ باقید:** مقاله‌های پیش‌چاپ/technical report که داوری یا تعمیمشان محدود است؛ گزارش‌های مهندسی شرکت‌ها برای تجربهٔ همان تیم، نه ارزیابی مستقل.
3. **محدود:** مخازن اجتماعی و prompt snapshots در `research/github/`; فقط برای ایده/نقشهٔ اکوسیستم و نه اثبات بهترین عملکرد یا صحت prompt داخلی.

## اختلاف‌ها/تغییرپذیری ثبت‌شده

- در جای‌گذاری دستور در متن بلند، راهنمای جاری Gemini می‌گوید پرسش را پس از زمینه بگذار؛ راهنمای Claude دربارهٔ دادهٔ طولانی و مدل‌های کنونی قواعد خاص خود دارد. نتیجه: دستورها/داده را مرزبندی کن و placement را روی مدل هدف eval کن؛ قاعدهٔ یکسان برای همه ادعا نمی‌شود.
- Anthropic (2024) می‌گوید ابتدا ساده‌ترین الگوی کارآمد را بساز؛ تجربهٔ سیستم پژوهش چندعاملی Anthropic نشان می‌دهد برای پژوهش باز و موازی‌پذیر، عامل‌های متعدد گاهی ارزشمندند ولی هزینهٔ توکن و هماهنگی بالا است. تناقض نیست: معیار، جنس کار و ارزیابی است.
- زنجیرهٔ فکر/تولید چندباره در paperهای 2022–23 روی مدل‌ها و taskهای مشخص مفید گزارش شده؛ راهنماهای مدل‌های استدلالی جدید کنترل effort را در لایهٔ API پیشنهاد می‌کنند و prompting طولانی/CoT اجباری را پیش‌فرض نمی‌دانند. برای دستیار عمومی فقط اعتبارسنجی متناسب با سختی را نگه می‌داریم، نه افشای reasoning خصوصی یا چندبارتولید دائمی.
- delimiter/یادآور prompt injection کمکِ احتمالی است؛ OWASP و مستندات vendor هیچ تضمین prompt-only ارائه نمی‌دهند. مرز واقعی باید در orchestration، schema، permission و تأیید انسان پیاده‌سازی شود.
